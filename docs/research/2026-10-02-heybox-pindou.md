## 官方文档对实现的影响

### 开发与预览

官方模板是标准 Web 页面，使用 Vanilla JavaScript 和 Vite。`hb-sdk dev` 的 Browser Mock 可以在未登录、未绑定小程序时启动；手机或 PC 真机调试另需 CLI 登录、远端绑定与有效启动票。旧版文档中“必须先登录才能预览”的说法不应作为当前 Browser Mock 的前置条件。

来源：[用户指定的 AI Agent 开发指南](https://docs.xiaoheihe.cn/hb_sdk/guide/ai-agent-development)、[CLI 指南](https://docs.xiaoheihe.cn/hb_sdk/guide/cli)。

### 构建配置

小程序资料与能力声明放在 `package.json#heybox`。本工具类别应为 `tool`；需要展示名称、200×200 图标、封面图片、平台列表和权限。Vite 使用无参 `miniappManifest()`。平台列表表示实际适配承诺，上架前需要对应客户端验收。

来源：[项目配置](https://docs.xiaoheihe.cn/hb_sdk/guide/project-configuration)。

### 图片导入与文件导出

原生文件接口需声明 `filesystem`，并在用户点击时调用选择器。Web 与 Browser Mock 不提供 SDK 文件能力；普通浏览器版需要独立使用 Web 文件选择和下载方式。不要把浏览器功能伪装成 SDK 已实现的原生能力。

原生 `saveFile()` 当前支持新 PC 和 iOS，Android 需考虑用户授权的可写目录等其他路径。应处理能力缺失、取消、重名和授权失效，不能只按操作系统推定可用。Android/iOS 的 `readBytes()` 有 8 MiB 完整读取上限，需要在导入前检查大小。

来源：[文件与沙箱](https://docs.xiaoheihe.cn/hb_sdk/guide/files-and-sandbox)、[FileHandle](https://docs.xiaoheihe.cn/hb_sdk/reference/symbols/root/interfaces/FileHandle.html)。

### 截图与完整图纸

`share.screenshot()` 截取可见窗口，不是任意尺寸的 Canvas 文件导出。移动端可提供截图分享，新 PC 当前禁用此能力。Mock 仅确认参数，不能验证真实截图。大图必须由图纸渲染器生成完整文件，或分块形成可读图纸，避免以窗口截图代替完整导出。

来源：[截图 API](https://docs.xiaoheihe.cn/hb_sdk/reference/sdk/share/screenshot.html)。

### 本地转换优先

官方文档当前说明 `network` 等需平台批准的权限尚未对外开放。本工具的缩放、颜色匹配和统计可以在本地进行；色卡应随应用打包，首版无需网络接口。使用文件、分享或设置存储时，只声明实际需要的权限。

来源：[权限声明](https://docs.xiaoheihe.cn/hb_sdk/guide/permissions)。

## 实现方式比较

| 方式 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| Web 转换核心 + 小黑盒适配层 | 共用图片算法；浏览器可预览；便于接入小程序 | 需要分别处理浏览器与宿主的文件能力 | 首选 |
| 仅普通网页 | 验证图片转换最快 | 后续仍需做小黑盒接入与真机验收 | 可作为同项目的开发入口 |
| Python 桌面程序 | 适合本地批处理 | 手机使用和小黑盒接入需要另写界面 | 不作为首版主线 |

建议采用本地计算的 Web 工具，并把浏览器与小黑盒的导入、保存、分享放在独立适配层。暂不引入登录、云端作品库或在线 AI 服务。

## 首版产品建议，方向已确认

### 使用流程

导入图片 → 选择图片处理方式 → 设置网格尺寸与 MARD 色卡范围 → 生成 → 查看图纸和用量 → 导出。

### 输入和尺寸

- 支持 PNG、JPEG、WebP，保留透明区域为空格。
- 像素模式采用最近邻采样；普通图片模式采用平滑缩小和颜色归并。用户可以手动选择处理方式。
- 预设网格建议包含 29×29、58×58，以及 32×32、64×64、96×96。
- 自定义宽高以“颗／格”为单位，默认保持原图比例，不静默拉伸；固定画布可等比留空。
- 自动尺寸：小型原生像素画可按一个原图像素对应一格；普通图片默认按长边 64 格等比缩小。放大后的像素截图不能直接把图片分辨率当作豆子数量，需要允许调整。
- 建议首版限制为每边 1–200 格；大图显示和导出均需尺寸预算。
- 图纸至少标明格数；实物尺寸作为可选项，按用户设置的底板孔距估算，不能把品牌或豆子直径直接当作所有底板的统一间距。

### 配色

- 首版 MARD，建议提供基础色卡与扩展色卡的选择。
- 保留色卡来源和版本；品牌色号是备料编号，RGB/HEX 是屏幕近似参考。
- 已找到 MIT 许可的社区数据源 `maxcleme/beadcolors`，仓库列出 Mard 291 色；尚未对每个色号、数据文件与实体套装做逐项验证。它不能标为“厂家官方精确色值”。
- 实施前需要固定来源版本、验证重复编号和合法颜色值，并保留许可信息。
- 建议允许限制实际使用颜色数量；匹配与归并完成后重新统计，保证数量表对应最终图纸。
- 品牌切换时重新匹配全部格子并统计，不能只替换色号文本。

数据候选来源：[BeadColors 原始仓库](https://github.com/maxcleme/beadcolors)。

### 输出

- 原图与转换预览；图纸可缩放查看。
- 每格一颗豆；细网格、每 10 格加粗线、行列坐标。
- 格内显示 MARD 编号，深色背景使用可读文字颜色；支持关闭编号查看效果。
- 输出宽高格数、实际豆子总量、颜色种数。
- 用量表包含品牌、色号、色块、数量；透明空格不计入任何颜色。
- 导出完整 PNG 图纸、PDF 设计图和 CSV 用量表；大图采用分块导出，保留全图坐标。
- 浏览器使用文件下载；小黑盒按实际文件能力保存。截图分享只作为移动端辅助功能。

### PDF 导出要求

- PDF 是正式导出格式，由当前生成结果直接生成文件，不能仅提供浏览器打印对话框或窗口截图。
- 默认使用 A4 页面；图纸排版独立设计，不复刻参考文件。
- 总览页显示作品预览、宽高格数、MARD 色卡版本、实际总豆数和颜色种数。
- 用量表包含色号、色块和实际数量，颜色较多时自动续页。
- 图纸页显示每格色号、细网格、每 10 格加粗线、全局行列坐标；空格有清楚且不混淆的标识。
- 按可打印区域和色号可读性自动决定每页格数，大图分块分页；不固定照搬参考文件的分块大小。
- 各分块页标明其在全图的位置、覆盖的行列范围和页码。分块不重复统计格子，全图总量与分块数量之和一致。
- 默认行列从 1 开始，页面、PNG、PDF 与数据导出使用同一套坐标约定。
- 默认图纸用于数格摆豆，允许放大打印，不宣称是底板实物比例。实物比例功能若加入，需根据用户设置的孔距生成，并提示以 100% 比例打印、关闭适应页面。
- 字体需要保证中文可显示；网格和色号应尽量采用矢量绘制，深色格使用浅色文字。
- 首版只列实际用量；若后续增加备料余量，需单独列出，不能改变实际豆子数量统计。
- PDF 与 PNG、CSV 共用最终格子数据和统计，避免各格式出现不一致。
- 通过浏览器或小黑盒文件适配层保存 PDF；下载和保存结束前不得提示成功。

### 验收要点

- 透明区域不计数，各色用量之和等于最终非空格总数。
- 单色图片得到可预期的色号和数量；色号必须来自所选色卡。
- 非正方形图片在默认设置下保持比例。
- 像素画边界保持清晰，普通图片可以缩小并控制用色数量。
- 自动、自定义、预设尺寸切换后，图纸和统计同步更新。
- 导出的 PNG 包含图纸、尺寸和清单；分块图能依坐标还原；CSV 数量与图纸一致。
- PDF 可以直接打开，包含总览、尺寸、可读网格、色号和用量表；每页坐标能定位到全图。
- 对单页图案、跨页图案、多色清单分别验证 PDF；重开文件检查页数和内容，渲染每页检查中文、色号、边界和分页，确保没有裁切、重叠或遗漏。
- PDF 各分块的非空格数之和等于全图实际豆数；PNG、PDF、CSV 的各色数量一致。
- 导入取消、坏图片、超出限制和宿主能力缺失得到可理解反馈。
- 浏览器可验收算法与页面；原生文件与分享必须另在实际客户端验收。
