# 拼豆图纸工作台设计规格

日期：2026-10-02。

范围依据：用户要求导入像素或普通图片，选择预设、自定义或自动尺寸，生成包含尺寸、网格、标准豆子色号和数量的拼豆图纸；用户确认 MARD 优先，后续支持其他品牌；用户要求 PDF 导出，并明确参考 PDF 不可照抄。用户已回复“继续做”确认首版方向，并回复“同意”批准本正式设计规格。状态：规格已批准，实施计划待审阅。

## 目标与首版边界

制作中文拼豆图纸工具，提供普通浏览器入口与小黑盒小程序入口。用户完成“导入图片 → 调整尺寸和颜色 → 生成图纸 → 查看用量 → 导出”即可获得能用于摆豆的图纸。

图片解码、采样、配色、统计及导出全部在本地完成。首版不需要账号、服务器、网络权限、云端作品库或在线 AI 服务。后续其他品牌使用相同色卡接口加入；首版不显示不能使用的品牌选项。

保留 PNG、PDF 和 CSV 三种导出。PDF 必须生成真正的文件，不能以浏览器打印对话框代替。参考 PDF 仅用于理解总览、分块阅读和备料需求，不复用其图案、配色、文案或版式。

## 技术组成

- 以官方 `hb-sdk create` 模板为基础，使用 Vite、JavaScript ES modules 和 Canvas 2D，不额外引入 UI 框架。
- 使用实际安装时核对的稳定版 `@heybox/hb-sdk`。本次文档学习核对到 0.8.4；Node.js 必须满足官方要求的 22.20.0 或更高版本。
- SDK 只从公开包入口导入，项目构建注册无参 `miniappManifest()`。
- PDF 使用随项目安装并打包的客户端库及中文字体；实施时核对库的公开 API 和字体许可。图纸格子、网格、坐标和色号采用矢量绘制。
- 使用 Node.js 内置测试工具检验纯算法；浏览器自动化检验真实导入、设置、导出和响应式布局。

模块职责：

| 模块 | 职责 | 输入与输出 |
| --- | --- | --- |
| 色卡 | 加载和验证本地颜色数据，提供基础／扩展范围 | 品牌、版本、颜色数组 |
| 转换核心 | 尺寸计算、RGBA 采样、最近颜色匹配、限制用色、统计 | 图片像素与设置 → 最终图纸数据 |
| 图纸绘制 | 预览、网格、坐标、色号及 PNG 排版 | 最终图纸数据 → Canvas |
| PDF 导出 | 总览、用量表、分块图纸及分页 | 同一份图纸数据 → PDF 字节 |
| 平台适配 | 浏览器与小黑盒图片选择、文件保存及可选分享 | 用户操作 → 文件数据／保存结果 |
| 页面 | 输入设置、生成状态、图纸查看、用量表、导出按钮 | 设置与结果的界面交互 |

## 页面和视觉

页面采用工具工作台布局：顶部显示“拼豆工作台”和导入按钮，桌面左侧为设置，中间为可缩放图纸，右侧为颜色清单。图纸占主要空间。手机按导入／设置、图纸、清单的顺序排列，导出按钮易于触达。

视觉以实际豆子色块和像素图纸为主体。背景 `#F6F7FB`，工作纸 `#FFFFFF`，正文 `#27243B`，主要操作 `#7562CA`，辅助背景 `#E4DFF5`，提示色 `#E09C60`。中文使用系统可用的微软雅黑／苹方字体。正文约 14–16 px，标题约 24 px，色号使用清晰等宽字体；PDF 使用内嵌许可合适的中文字体。

不以营销首屏占据空间。首次打开可展示一个独立绘制的原创像素示例，明确标为示例，并提供导入操作。示例不取自用户参考文件。所有控件有文字标签和键盘焦点，状态信息不只依赖颜色。

## 图片输入

- 接受 PNG、JPEG 和 WebP，一次处理一张图片；拒绝不能解码的文件。
- 单文件上限 8 MiB；解码图片最大 1600 万像素且任意边不超过 8192 像素。超限给出缩小图片的提示，保留现有结果。
- 支持“像素画”和“普通图片”两种明确模式，用户可切换。像素模式采用最近邻采样；普通模式采用平滑缩小后匹配色卡。
- 支持带透明区域的图片。采样后 alpha 小于 128 的格子为空格；其他半透明格与白色合成后匹配。说明这一规则，避免背景是否计数含糊。
- 首版只保留透明背景为空格，不承诺识别和移除任意照片背景。
- 更换图片时释放旧的临时对象 URL；解码失败不能清除上一份可用图纸。

## 尺寸设置

“尺寸”默认表示宽 × 高的格数，每个非空格对应一颗豆。

- 预设：29×29、58×58、32×32、64×64、96×96。
- 自定义：宽高均为 1–200 的整数；拒绝空值、小数、非数字和超出范围的值。
- 默认等比放入目标画布并居中，留空格；用户可关闭保持比例，以明确选择拉伸。
- 自动尺寸：像素模式下，两边均不超过 200 的原图按原生像素大小；更大的像素图和普通图片按长边 64 格等比计算，短边四舍五入且至少 1 格。
- 自动尺寸只依据图片分辨率和模式，不宣称能识别被放大的像素截图的原始像素单元。
- 用户改变尺寸后明确显示待生成状态；点击“生成图纸”统一更新预览、清单和导出数据。
- 可选底板孔距以毫米输入，范围 1–10；显示宽高格数乘孔距的估算占用尺寸，并标为估算。没有设置孔距时只显示格数。

## MARD 配色和数量

- 默认 MARD 基础范围，允许切换扩展范围。基础／扩展成员以固定来源的数据为准，不简单截取数组前 221 项。
- 数据须来自许可允许使用的来源，固定版本并保留来源和许可证。候选为 MIT 许可的 `maxcleme/beadcolors`；实施前核对原始数据、成员数、色号唯一性和 RGB 合法性。
- 数据结构包含品牌、色卡版本、来源、色号、RGB 和可选名称。网页与导出均说明色值是屏幕参考，不能称为厂家官方精确测量值。
- 将输入颜色变换到 CIELAB 后按颜色距离匹配；透明空格不参与配色。
- 使用颜色上限可选“不限制、8、16、24、32、48”；默认 24。限制开启时，根据图像实际颜色分布选择代表色，再映射到可用豆子色卡，不优先选择仅由数量排序的背景色。
- 默认不使用抖动，避免产生大量难以摆豆的孤立杂色。
- 统计只从最终格子数据生成。各色数量之和必须等于非空格数量，透明留空不计入任何颜色。
- 清单显示品牌、色号、色块、实际数量，默认按用量降序。首版不添加备料余量或购买建议。

## 最终图纸数据

每次生成得到不可混用的结果快照：宽、高、按行排列的格子色号或空值、所用色卡及版本、各色统计、非空格总数、颜色种数和生成设置。界面、PNG、PDF、CSV 消费同一快照。更改设置不会把旧图纸与新清单拼在一起。

所有格式使用从 1 开始的行列坐标。格子保持正方形。细网格每格显示，每 10 格加粗；深色格使用浅色编号，浅色格使用深色编号；空格显示轻量标识并说明其无需摆豆。预览允许切换网格、色号和缩放。

## PNG 和 CSV

- PNG 包含作品名、尺寸、图纸、MARD 版本、总数量及用量表。大图按 Canvas 尺寸预算自动调整格子显示尺寸；导出失败需要清楚提示，不能下载空白文件。
- CSV 使用 UTF-8 BOM，字段为品牌、色卡版本、色号、颜色名称、HEX、实际数量；正确转义文件名以外的字段，数量与当前快照一致。
- 导出文件名由安全处理的作品名生成，不能含路径分隔符或操作系统不允许的字符。

## PDF

- 默认 A4 竖版，约 15 mm 页边距，保留页眉页脚。
- 总览页显示作品预览、宽高格数、色卡版本、颜色种数、总豆数和可选估算尺寸。
- 用量表包含色号、色块及实际数量；颜色较多时续页并重复表头。
- 图纸页按可打印区域、至少 5 mm 的格子边长和至少 7 pt 的色号文字自动分页。较长色号需要保证完整显示，可减少每页列数。
- 每页标注分块位置、覆盖的全局行列范围、分块用量和页码，可用小定位图标明其在全图中的位置。
- 所有分块恰好覆盖图纸范围，不重叠计数，不漏最后一行或列。边缘分块可小于整块。
- 空格、编号对比度和每 10 格的辅助线与预览语义一致。
- 中文字体嵌入，色号和网格采用矢量，图片总览可以栅格嵌入。无需用户联网获取字体。
- 首版 PDF 用于数格摆豆；图纸页放大到便于阅读，不提供实物比例打印开关。
- 实际 PDF 必须重开检查页数，渲染全部页面检查文字、边界、分页、清单续页和分块完整性。

## 小黑盒和浏览器

- 普通浏览器使用自己的文件输入与 Blob 下载，不伪装为已实现的 SDK 文件接口。
- 小黑盒导入通过用户点击直接调用 `files.pickFiles()`；在 SDK 就绪前禁用原生能力按钮，不能在点击里先等待握手后才打开选择器。
- 文件保存优先使用已支持的 `files.saveFile()`。能力缺失时，由新的明确用户操作选择可写目录并写入文件；不静默替用户授权。
- 分别处理取消、能力缺失、授权撤销、重名及 I/O 错误。用户取消不弹报错。
- 声明 `filesystem`；若实现截图分享，再声明 `share`。首版不声明 `network`、`companion` 或 `userInfo`。
- 小程序 `category` 为 `tool`，填写合法名称、200×200 图标、封面与实际适配的平台。绑定和登录仅在真实客户端调试阶段进行。
- 本地 Browser Mock 不支持 SDK 文件 I/O，网页算法与文件入口单独验收。小黑盒的原生导入、保存和可选分享必须由对应真实客户端验收后才能报告已验证。
- 不提交审核、不公开发布，除非用户后续明确要求。

## 性能和错误状态

生成及导出期间显示进行状态，防止重复提交。处理最大 200×200 格图纸时使用分批计算或 Worker，避免长时间阻塞操作。图片读取和 PDF 导出失败保留现有结果并允许重试。快速更换输入时旧任务不能覆盖新任务结果。

## 验收

1. 单色、不同比例、带透明空洞及 1×1 图片均能生成正确尺寸和数量。
2. 像素和普通模式、所有尺寸方式、保持比例与拉伸、颜色上限行为明确且可验证。
3. 所有最终色号属于当前色卡，颜色上限不被超出，清单总量等于非空格数量。
4. 非整块倍数的大图能正确分块，分块范围唯一且完全覆盖图纸。
5. PNG、PDF 和 CSV 从同一结果生成，各色数量与总量一致。
6. PDF 总览、图纸及多页清单没有缺字、乱码、重叠、裁切或难以识别的色号。
7. 浏览器通过真实图片导入和导出流程，在桌面和窄屏布局均可使用；拒绝非法尺寸、坏文件和超限图片。
8. 项目通过算法测试、浏览器验证和 `hb-sdk build`；`doctor` 核对实际 SDK 与官方 Skill 匹配。
9. 未执行的真机验收明确列出，不把 Mock 参数确认说成真实文件保存或截图成功。
