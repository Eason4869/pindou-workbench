## 本版功能

导入 PNG/JPEG/WebP、像素或照片采样、自动/预设/自定义 1–200 格、等比补齐、用色数量限制、MARD 221/291 色、网格/坐标/色号、每色实际用量，以及 PNG/CSV/PDF 导出。PDF 包含 A4 总览、用量清单与分块格子图。全部图片本地处理，不上传。

首版只提供 MARD，其他品牌已预留注册表扩展。屏幕 RGB 是公开参考数据，配色请以实物为准。PDF 约 6 MiB，含内嵌中文字体；孔距只用于成品尺寸估算，PDF 不作为真实底板尺寸的定位模板。

## 发布网页版

1. 解压 `pindou-web-1.0.2.zip`。
2. 将解压出的**整个目录内容**上传到静态托管服务；站点根目录或 `/pindou/` 等子目录均可，资源采用相对路径。目录地址保留结尾 `/`。
3. 服务器需正常提供 HTML、CSS、JavaScript 与 Worker 文件，JavaScript MIME 类型为 `text/javascript` 或 `application/javascript`。使用 HTTPS；不需要后端、数据库、CDN 或 API 密钥。
4. 打开线上页面，导入一张透明 PNG 和一张照片，再下载 PNG、CSV、PDF，确认数量与界面一致，PDF 中文及色号完整。

不要直接双击 `index.html` 用 `file://` 打开，模块和 Worker 需要 HTTP(S)。不要删除 `assets/` 内按需加载的字体脚本。若托管方额外设置 CSP，需允许同源模块脚本、同源 Worker、本地 `blob:` 图片/下载及 Canvas 导出；独立网页与小黑盒的 CSP 不共用配置。

需要本机验证生产包时，在解压目录运行已有的静态服务器，例如：

```powershell
python -m http.server 8080 --bind 127.0.0.1
```

然后打开 `http://127.0.0.1:8080/`。Python 仅用于此示例服务器，不是网页运行依赖。

## 提交小黑盒版本

小黑盒 CLI 提交时会从当前项目重新构建并上传，不能把上述 ZIP 当作已提审或已发布版本。解压源码包，在 `app/` 内运行：

```powershell
npm ci --legacy-peer-deps
npm run hb-sdk -- login
# 已有小程序时，将下面的 ID 替换为真实 ID
npm run hb-sdk -- remote bind <mini-program-id>
# 没有已有项目时，改用 npm run hb-sdk -- remote create
npm run dev
```

Node.js 需要 22.20.0 或更高版本。绑定和登录由官方 CLI 管理，不将 Cookie、token 或账号密码写入源码。

通过官方 Host 在真实客户端完成导入、取消、PNG/CSV/PDF 保存、目录降级、同名文件及授权撤回检查。当前 `heybox.platforms` 仅声明 Android；用户已确认 Android 扫码进入成功，文件保存验收结果另行记录。其他平台完成真实客户端验收后再加入声明并发布新版本。Browser Mock 禁止 iframe 下载，不能代替真实客户端文件保存验收。

验收完成后提交审核：

```powershell
npm run deploy -- --auto-publish --release-note "1.0.2：图片转换、MARD 图纸与用量统计，支持 PNG/CSV/PDF 导出，手机安全区适配；作者彧晟Eason。素材来源详见随包 THIRD_PARTY_NOTICES.md"
```

上述命令构建、上传、提交审核，并设置审核通过后自动发布。如果此前没有开启自动发布，审核通过且核对目标小程序后：

```powershell
npm run hb-sdk -- remote release 1.0.2
```

如果远端已存在 1.0.2，需要先选择未使用的新版本，并同步修改 `package.json` 和锁文件再构建。当前源码已绑定小程序草稿。登录态由 CLI 在设备上管理，GitHub 仓库及提交记录不包含凭据。提审、审核与上线状态另行核对，不能以本地 ZIP 代替平台发布结果。

官方发布流程依据：<https://docs.xiaoheihe.cn/hb_sdk/guide/cli>；项目配置及平台验收要求：<https://docs.xiaoheihe.cn/hb_sdk/guide/project-configuration>。本任务已于 2026-10-03 重新读取官方 `llms.txt`、CLI、项目配置、兼容性和更新日志；0.8.4 与当前稳定版日志一致。

## 重新构建

在源码包 `app/` 目录内：

```powershell
npm ci --legacy-peer-deps
npm test
npm run test:e2e
npm run build:web
npm run build
npm run verify:production
```

`dist-web/` 是网页版，`dist/` 是小黑盒版，不能混用。端到端测试需要 Microsoft Edge；独立 PDF 渲染测试需要 Poppler，没有时该项会跳过。构建与运行无需 Python 或 FontTools，预处理字体已随源码提供。

两种 npm 构建会先同步原始许可文件至 `public/`，后续官方 CLI 重新构建时仍保留这些文件。构建和生产验证完成后，若需重新生成 ZIP，使用 Python 3 标准库工具：

```powershell
python scripts/package-release.py --date 2026-10-03
```

打包工具拒绝覆盖已有版本目录，校验锁文件与 Manifest 版本一致，逐个校验 ZIP 中的 CRC 与文件 SHA-256。需要再次交付时先使用新的版本号并补齐对应发布说明。
